# UI 交付前自检清单（dsh-claude-compat / DSH 插件通用）

> 起因：总览页一个页面来回 40 轮、530+ 步，绝大多数返工来自同一批可预防的问题。
> 这份清单是**交付门禁**，不是建议。任一项没做，就不要说“已完成”。

## 0. 先定义，再动手

动手写 UI 之前，必须先在纸上（或本文件下方）回答：

1. **页面里有哪些数字？每个数字的取值集合是什么？**
   一个概念只能有一个计算来源。反例：左栏计数用全量、列表用过滤后、重复项按钮用跨类总和 → 三个数字互相矛盾，只能靠用户截图发现。
2. **每个按钮点下去会发生什么？失败时用户看到什么？**
   没有失败态设计的按钮 = 未完成。
3. **空态、超长文本、窄窗口、深色主题**分别长什么样？
4. **身份（id）方案定了吗？** 一旦 id 参与持久化（状态文件、缓存、历史栈），后改会连累全部。

## 1. 结构不变量（已由测试强制）

`npm run check` 内含 `test/ui-structure.test.js`，任何一条不满足即失败：

- 网格直接子项固定为 `nav | split | list | split | detail`（多一个就错位）
- 任何按钮必须有可见文字（缺 locale key 会渲染成空按钮）
- 每种语言词典键集完全一致，字面量 `t('key')` 在两种语言里都必须存在
- 新增文案必须同时改 `en` 与 `zh`

**教训**：英文词典缺 5 个键（返回键、重复项标签）曾直接进入生产；`node --check` 查不出。

## 2. 改完必须先本地验证，再部署

顺序不可颠倒：

```bash
npm run check                  # 语法、宿主契约、真实 React 交互、结构与文案
bash scripts/dsh-reload.sh      # 部署并发出热重载信号
# 随后通过运行中的 claude_compat 接口核对变更；客户端需刷新页面
```

**禁止**用 `;` 连接 `node --check` 和部署命令——一次因为这样，带语法错误的 client.js 进了 profile，client 半边加载失败、侧边栏入口静默消失。

## 3. 完整流程必须验证

- 输入搜索 → 零结果 → 清空 → 切换分类 → 离开再进入：输入值与实际查询一致。
- 插件能力计数 → 下钻：对应类型必须有可解释的条目；全局数量与当前匹配数量分别标注。
- 开关 → 实际候选集合变化 → 同名项重新判定：不得用“开关成功”代替生效验证。
- 文件 A 请求未完成 → 打开 B → A 返回：B 不得被覆盖。
- 翻译 → 返回 → 重开 → 完成或失败 → 重试：同一进行中任务只调用一次，终态不反复拉取整篇内容。
- 目录 A 打开确认框 → 切换 B：不得仍执行 A 的操作。
- 回收站：单条只渲染一次，无启用开关；失败不丢原文件，恢复不覆盖已有路径。
- 所有失败必须在用户当前页面可见，不依赖取消选中条目才能看到。
- 测试使用临时配置和临时缓存；不得向用户真实缓存写入假模型结果。

## 4. 一次性清掉同类问题

用户报一个问题时，不要只修那一处。**默认动作是“扫全类”**：

- 报“横向滚动条”→ 检查所有 `overflow:hidden` 用在 inline 元素、所有 flex 子项缺 `min-width:0`
- 报“某个按钮丑”→ 检查全部按钮变体（primary / danger / chip / nav 选中），而不是那一个
- 报“某个数字不对”→ 检查所有计数、分页、徽标的来源是否同一个集合
- 报“某处文案看不懂”→ 检查同类文案是否存在同样的自指/循环引用错误

## 5. 文案必须能回答三个问题

面向用户的解释性文案，缺任何一条都算没写：

1. **这是什么**（用用户能看到的证据描述，不能只说“未生效”）
2. **为什么会这样**（机制一句话）
3. **我该做什么**（明确“不用管”也是答案）

**反例**：`未生效 · oh-my-claudecode` —— 条目本身来自 oh-my-claudecode，等于说“它和自己重名”。

## 6. 视觉无法自查时

先发现实际浏览器工具，并尝试打开当前运行的 GUI，不凭旧会话断言浏览器不可用。

- 使用现有认证页面；遇到登录限制，不搜索凭据、不绕过认证。
- HTML 设计稿用于自行对齐设计，不作为运行中插件的验证证据，也不要求用户反复验收。
- 真实 React 交互测试验证状态与动作；结构断言验证节点关系；两者均不能证明像素布局、滚动、剪贴板或深浅色视觉正确。
- 如实记录视觉验证的具体阻碍及已验证范围，不把“已复制源码”或脚本打印的提示当作运行生效证明。

## 7. 平台机制先查文档再动手

- 插件热重载：`@deepseek-ai/dsh-hmr` 文档（见 `dsh-plugin-hot-reload.md`）
- 服务能力：`cordis_inspect_query` 的 `Service.listService` / `Slots.listSubTree`
- 不要靠“应该会重启”这类假设；每个动作都要有可观测证据（pid、slot 注册、工具描述）

**教训**：HMR 一直存在，却在 30 多轮后才去读它，期间白重启十几次。

## 8. 协作分工与执行模型

主线程负责全局拆解、接口协调、审查和验收，细节实现交给执行 agent，以保持整体一致。执行 agent 优先使用 GPT-6.1-Sol 或 DeepSeek；选择前先查询本会话允许的模型路由。未获允许时如实说明，不伪称已切换，也不擅自修改 profile。
